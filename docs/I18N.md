# French / Arabic interface (IDA-UI-2)

**Status:** implemented on every page (workshop, operator console, sign-in, public home and passport).

## How it works

| Piece | Role |
|---|---|
| `reference/i18n.js` | The layer, shared by every surface (`/admin/i18n.js`, `/atelier/i18n.js`, `/login/i18n.js`, `/assets/i18n.js`). French is the source language; in Arabic it translates the page's text and the `placeholder`, `aria-label`, `title`, `alt` attributes on load and again whenever a script changes the page (MutationObserver), so text built by the page scripts is translated without a second copy of any page. |
| `reference/i18n-catalog-ar.js` | The catalogue, **generated** by `ops/ui/i18n/build-catalog.py` from `ops/ui/i18n/strings-*.json` (`{ "French": "Arabic" }`) and `templates.json` (`["Face {0} enregistrée.", "تم حفظ الوجه {0}."]`). Edit the JSON, then rebuild. |
| Counters | a key may use `#` for a number: `"# véhicule(s) · page # sur #": "# مركبة · الصفحة # من #"`. |
| Composite lines | a line made of parts joined by `·` or `—` is translated part by part, only when every part is known. |
| `reference/i18n-serve.js` | The server reads the `ida_lang` cookie and serves `<html lang="ar" dir="rtl">`: an Arabic page is laid out right to left from the first byte, before any script runs. |

**Never translated:** plates, IVIDs, VINs, codes, e-mail addresses — anything inside `<code>`, `<bdi>`, `.ida-plate`,
`.ida-ivid`, `[translate="no"]` or `[data-i18n-skip]`. Data typed by people (makes, names, reasons) stays as typed.

## The language choice

- Selector in the top bar of every signed-in page, on the sign-in page, in « Mon compte », and in the public header.
- Stored in the `ida_lang` cookie (`fr` | `ar`, one year, `SameSite=Lax`, `Secure` over HTTPS) — never in browser
  storage, the rule every authenticated page follows. It survives sign-in, sign-out and refresh, and applies to every route.
- Changing it reloads the page in the new language and direction.

## Right to left

Layout uses CSS logical properties (`margin-inline-start`, `inset-inline-end`, `border-inline-start`…), so the same
rules lay out both directions; the few direction-specific rules are under `[dir="rtl"]` (sidebar drawer, collapse
icon). Plates keep their left-to-right order inside Arabic text (`<bdi dir="ltr">`). Dates and numbers use the page
language with Western digits (`ar-TN-u-nu-latn`), the usage in Tunisia.

## Server messages

API errors carry `message_fr`; the page shows it, and the layer translates it like any other text (the server's
French messages are in the catalogue).

## Completeness check

`tests/ida-ui-browser-test.js` opens every page in Arabic and fails on any visible interface text left in French
(data such as makes and names excepted). To find what is missing while developing:
`python3 ops/ui/i18n/build-catalog.py` after adding entries.
