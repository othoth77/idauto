# ID Auto — Mythos Identity Adapter Specification

**Status:** SPECIFICATION ONLY. `identity.js` was **not modified** by stage `MYTHOS-IDENTITY-CORE-0` and its runtime behaviour is **unchanged**.

**Origin contract:** `docs/MYTHOS_IDENTITY_ARCHITECTURE.md` in `othoth77/mythos-prod` — §2 identifier, §3 model, §6.1 migration, §7 non-scope. **External and optional.** That document is not part of this repository and IDauto does not depend on it; it is cited because this adapter was specified against it. The standalone successor is the W3C DID/VC identity work scheduled at IDA-7 — see [`../protocol/credentials/README.md`](../protocol/credentials/README.md) and [`../docs/ROADMAP.md`](../docs/ROADMAP.md).

---

## 1. What exists today

`reference/identity.js` (stage `IDA-2E-PRE`) parses the `IDAUTO_ADMIN_IDENTITIES` environment variable — a JSON object mapping operator-provisioned bearer tokens to stable identity strings — and exposes:

```js
resolveIdentity(token)   // -> identity string | null
clearIdentityCache()     // test/ops helper
```

It is an explicitly-labelled stopgap, **not** authentication. It has no user table, no credential store, and no concept of an organisation or a role. That characterisation is unchanged by this stage.

## 2. What the contract now requires

Only the **format of the resolved value** is constrained. The mechanism is untouched.

| Aspect | Before | After the contract |
|---|---|---|
| Storage of the map | `IDAUTO_ADMIN_IDENTITIES` env var | **unchanged** |
| Token format | operator-chosen opaque secret | **unchanged** |
| Resolved identity value | arbitrary string | **MUST be `usr_<uuidv7>`** |
| Value written to `actor_ref` | the resolved string | **unchanged mechanism**, now canonical form |
| Anything about credentials | out of scope | **still out of scope** |

The resolved value is what `withAudit()` already persists into `idauto_audit_log.actor_ref VARCHAR(64)`. A canonical identifier is 40 characters, so **no column change is required** — this is the reason the contract chose a string identifier (see §2 of the binding decision).

## 3. Target interface

Any component that turns a caller-supplied credential into an identity must satisfy:

```
resolveActor(credential) -> { mythos_user_id, actor_type } | null
```

- `mythos_user_id` — canonical `usr_<uuidv7>`; validate with `isValidUserId()`
- `actor_type` — one of `system | contributor | professional_user | admin | anonymous`
- `null` — credential not recognised (callers MUST treat this as unauthenticated)

`projects/mythos-core/reference/identity-contract.js` provides `assertResolvedActor(result)` so an adapter can self-check its own output **without the contract module ever seeing the credential**.

The existing `resolveIdentity(token) -> string | null` already has this shape; the adapter change is (a) values become canonical, and (b) an `actor_type` accompanies the identifier.

## 4. Migration procedure (NOT executed by this stage)

1. Mint one canonical identifier per existing admin token — `identityContract.newUserId()`.
2. Re-issue `IDAUTO_ADMIN_IDENTITIES` with the same token keys and canonical values. **Token secrets themselves do not change**, so no operator credential rotation is required.
3. Extend `identity.js` to return `{ mythos_user_id, actor_type }`, keeping `resolveIdentity()` as a thin backward-compatible wrapper until callers are updated.
4. Update `api.js`/`writes.js` call sites to consume the object form.
5. Re-run the full ID Auto suite.

**No stored data requires rewriting.** `idauto_user_roles` and `idauto_contributors` hold **0 rows**, and `idauto_audit_log`'s existing rows are synthetic test fixtures regenerated by the suites. The audit log is append-only by design and **MUST NOT** be rewritten under any circumstances.

## 5. Hard constraints

- **Never** write a bearer token, credential, email, or any personal data into `actor_ref`. It carries only a canonical `usr_`/`svc_` identifier or `NULL`.
- **Never** log the raw value of `IDAUTO_ADMIN_IDENTITIES`; the current parse-failure path already avoids this and must keep doing so.
- The adapter performs **no** credential verification beyond exact map lookup. It is not authentication and must never be described as such.
- ID Auto **must not** add the core's format `CHECK` constraints to its own columns — those belong to `mythos_core` only, so products stay decoupled from core's internal validation.
- The deferred additive `mythos_org_ref` column on `idauto_organizations` (binding decision §6.6) is **out of scope**. `idauto_organizations.id` remains `SERIAL`; retyping a live primary key with dependent foreign keys is expensive and avoidable.

## 6. Out of scope

Real authentication, credential storage, provider/federation tables, token issuance or validation, MFA, and any authorisation evaluation beyond a role comparison. See the binding decision §7.
